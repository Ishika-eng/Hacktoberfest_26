# Benchmark

Each row is one model on one app, run several times with `agent/migrate.py`. Generated by `agent/bench.py` on 2026-10-22.

**Hardware:** Apple M3 Pro, 18 GB RAM, Darwin 27.0.0
**Agent version:** commit `4e76ec2`; the cheat sheet was last changed in `dc3b7e2`
**Ollama:** 0.40.3
**Models:**
- `qwen2.5-coder:7b-instruct`: 7.6B parameters, Q4_K_M quantization, qwen2, digest `dae161e27b0e`
**Upgrade tool:** OpenRewrite `UpgradeSpringBoot_3_3` (rewrite-spring 6.37.1), then the model fixes what is left.
**Warning: 2 run(s) used the built-in fallback because OpenRewrite failed** (for example the held-out app, which has Gradle files). Those rows are not OpenRewrite results; see each report.
**Sampling:** temperature 0, seed 0, 8192-token context, up to 5 model rounds, 30 s per-test timeout.

**Held-out apps** (not written by us, pinned commits in `agent/heldout/manifest.json`): `heldout/spring-petclinic`. The cheat sheet was frozen before these runs; see `agent/heldout/README.md`.

How to read it:
- *Runs passed*: runs that ended with all tests green and passed every integrity check (same tests executed as the Boot 2 baseline, no test or build file changed). A pass can still carry security differences.
- *Tests passed* is passed/total in the final build. The first row of each app, with no model, is the baseline: what OpenRewrite alone achieves (an app that does not compile runs no tests, shown as `-`).
- *Security diffs* is endpoint checks whose HTTP status differs between the Boot 2 build and the upgraded build, out of all checks (every role x the endpoints in the app's `endpoints.json`). A pass with differences means the tests are green but behaviour changed.
- *Same code every run?* compares a fingerprint of the generated sources. With temperature 0 and a fixed seed on the same machine the output is often identical; where it is, the repeated runs are one result seen several times, not independent samples. Where it is not, small differences between rows are noise.
- Times include model loading. Per-round prompts and replies are in `reports/benchmark/logs/`; full reports are in `reports/benchmark/`.

**This benchmark is incomplete, on purpose.** DeepSeek-Coder has not been run with the corrected setup, and Petclinic has a single Qwen run. Earlier published numbers came from runs where a bug made the agent use its built-in fallback instead of OpenRewrite (OpenRewrite silently skips folders a `.gitignore` ignores); those numbers were removed.

**Which agent version produced which rows.** The `sample-app` and `sample-jpa-app` Qwen rows were made with the agent version named in the header. Before that version, Qwen **failed `sample-jpa-app` 3 of 3** (about 151 s each): the model's `Product.java` rewrite was right but used `@Column` without importing it and left a stale `@Override`, so the attempt scored worse and was rolled back. The agent was then changed to repair such slips (known imports, `@Override` the compiler rejects) before an attempt is judged, and the runs were repeated. That change was made after seeing these results, so the pass is not an independent test of the fix. The baseline rows and the single Petclinic row were made with the previous agent version (`7c80c4c`); the change does not touch them (no model attempt is judged in the baselines, and Petclinic stops on a `pom.xml` error).

What the rows show:
- **`sample-app`**: Qwen passes 3 of 3 with one model round, and writes byte-identical code each time (same fingerprint), so these are one result seen three times, not three independent samples. All 18 security checks answer the same as the Boot 2.7 build.
- **`sample-jpa-app`**: Qwen passes 3 of 3, again with identical code each time. The model rewrites `Product.java`; the agent's own repairs add the missing import and drop the stale `@Override`. All 8 tests are green, yet 2 of 24 security checks differ: `GET /products/` goes from 200 to 404 for logged-in users, because Spring 6 no longer matches a trailing slash. No test covers it.
- **Petclinic (first run, agent `7c80c4c`)**: OpenRewrite crashed on the project's Gradle files, so the weak built-in fallback ran (flagged above). The build then fails on `mysql:mysql-connector-java`, a `pom.xml` problem the agent cannot edit, and the model's rounds on unrelated Java files changed nothing.

The two unseen apps have their own reports outside this table: after the agent was changed to ignore Gradle files, spring-petclinic passes with OpenRewrite alone (0 model rounds; no longer held-out), and spring-petclinic-rest, run once untuned, fails on build-time generated `javax` code. See the README's *Held-out tests* and `reports/history/`.

Reproduce: `python3 agent/bench.py` (needs Ollama with the models pulled, JDK 17+, Maven).
