# Benchmark

Each row is one model on one app, run several times with `agent/migrate.py`. Generated by `agent/bench.py` on 2026-10-22.

**Hardware:** Apple M3 Pro, 18 GB RAM, Darwin 27.0.0
**Agent version:** commit `7c80c4c`; the cheat sheet was last changed in `dc3b7e2`
**Ollama:** 0.40.3
**Models:**
- `qwen2.5-coder:7b-instruct`: 7.6B parameters, Q4_K_M quantization, qwen2, digest `dae161e27b0e`
**Upgrade tool:** OpenRewrite `UpgradeSpringBoot_3_3` (rewrite-spring 6.37.1), then the model fixes what is left.
**Warning: 2 run(s) used the built-in fallback because OpenRewrite failed** (for example the held-out app, which has Gradle files). Those rows are not OpenRewrite results; see each report.
**Sampling:** temperature 0, seed 0, 8192-token context, up to 5 model rounds, 30 s per-test timeout.

**Held-out apps** (not written by us, pinned commits in `agent/heldout/manifest.json`): `heldout/spring-petclinic`. The cheat sheet was frozen before these runs; see `agent/heldout/README.md`.

How to read it:
- *Runs passed*: runs that ended with all tests green and passed every integrity check (same tests executed as the Boot 2 baseline, no test or build file changed). A pass can still carry security differences.
- *Tests passed* is passed/total in the final build. The first row of each app, with no model, is the baseline: what OpenRewrite alone achieves (an app that does not compile runs no tests, shown as `-`).
- *Security diffs* is endpoint checks whose HTTP status differs between the Boot 2 build and the upgraded build, out of all checks (every role x the endpoints in the app's `endpoints.json`). A pass with differences means the tests are green but behaviour changed.
- *Same code every run?* compares a fingerprint of the generated sources. With temperature 0 and a fixed seed on the same machine the output is often identical; where it is, the repeated runs are one result seen several times, not independent samples. Where it is not, small differences between rows are noise.
- Times include model loading. Per-round prompts and replies are in `reports/benchmark/logs/`; full reports are in `reports/benchmark/`.

**This benchmark is incomplete, on purpose.** It was paused to free the machine: DeepSeek-Coder has not been run with the corrected setup, and Qwen has one Petclinic run instead of three. Earlier published numbers for both models came from runs where a bug made the agent use its built-in fallback instead of OpenRewrite (OpenRewrite silently skips folders a `.gitignore` ignores); those numbers were removed. The only trustworthy rows are the ones above.

What the rows show:
- **`sample-app`**: Qwen passes 3 of 3 and writes byte-identical code each time (same fingerprint), so these are one result seen three times, not three independent samples.
- **`sample-jpa-app`**: Qwen fails 3 of 3, and its final code is identical to OpenRewrite's own output (same fingerprint as the OpenRewrite-only row). Every model attempt scored worse than where it started and was rolled back. The model's `Product.java` rewrite was right but used `@Column` without importing it, and the import repair did not know that class, so the fix counted as one error swapped for another. This is a gap in the agent, not fixed yet.
- **Petclinic (held-out)**: OpenRewrite crashed on the project's Gradle files, so the weak built-in fallback ran (flagged above). The build then fails on `mysql:mysql-connector-java`, a `pom.xml` problem the agent cannot edit, and the model's rounds on unrelated Java files changed nothing.

Reproduce: `python3 agent/bench.py` (needs Ollama with the models pulled, JDK 17+, Maven).
