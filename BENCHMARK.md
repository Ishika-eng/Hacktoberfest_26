# Benchmark

Each row is one run of `agent/migrate.py` on one sample app. Generated by `agent/bench.py` on 2026-10-22.

**Hardware:** Apple M3 Pro, 18 GB RAM, Darwin 27.0.0
**Upgrade tool:** OpenRewrite `UpgradeSpringBoot_3_3` (rewrite-spring 6.37.1), then the model fixes what is left.
**Settings:** temperature 0, 8192-token context, up to 5 model rounds, 30 s per-test timeout.

How to read it:
- *Runs passed*: runs that ended with all tests green and no test file modified. A pass can still carry security differences.
- *Tests passed* is passed/total in the final build. The first row of each app, with no model, is the baseline: what OpenRewrite alone achieves (an app that does not compile runs no tests, shown as `-`).
- *Security diffs* is endpoint checks whose HTTP status differs between the Boot 2.7 build and the upgraded build, out of all checks (3 roles x the endpoints in the app's `endpoints.json`). A pass with differences means the tests are green but behaviour changed; each one is flagged for a human.
- Models are not perfectly repeatable even at temperature 0, so each cell is run several times. Small differences are noise. Times include model loading.
- Per-round prompts and replies are in `reports/benchmark/logs/`; full reports are linked by name in `reports/benchmark/`.

**DeepSeek-Coder was stopped early on purpose.** After 2 runs on `sample-app` (both 8/11) and 1 run on `sample-jpa-app` (3/8) it was clearly not converging, and each run takes 4 to 14 minutes, so the remaining runs were skipped. Its three finished runs are reported above, unedited; the unfinished runs are not counted.

Two things explain DeepSeek's failures, one on each side of the harness:
- The model rewrites the security config with `httpBasic(AbstractHttpConfigurer::disable)` (turning HTTP Basic off) or otherwise leaves the app answering 403 where the original answered 200 or 401. The security check confirms it: 10 of 18 checks on `sample-app` and 16 of 24 on `sample-jpa-app` changed.
- **Known harness weakness, not fixed:** once the build compiles but tests fail, the agent chooses files to fix from the stack trace. DeepSeek's later rounds went to `ApiController`, `DemoApplication`, `Order` and `ShopApplication`, files that were not the problem, and never returned to `SecurityConfig`. A better file choice might change DeepSeek's result, so do not read these rows as proof the model cannot do the task.


Reproduce: `python3 agent/bench.py` (needs Ollama with the models pulled, JDK 17+, Maven).
